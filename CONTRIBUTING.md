# Contributing to bkey

Thanks for taking the time to contribute!

## Reporting a bug

The fastest way: open the app → **Settings → Error log → 📧 Email developer**. It sends the crash/error details straight to the maintainer, with the context needed to actually fix it.

You can also [open a GitHub issue](../../issues/new) or email **lvl60me@gmail.com** directly — same address for suggestions and feedback.

Before filing, please check it's not already covered by an [open issue](../../issues) or the README's FAQ.

## Suggesting a feature

Open an issue describing the problem it solves (not just the feature itself) — that makes it much easier to evaluate and, if it fits the project's scope, implement well.

## Building the project

See [BUILDING.md](BUILDING.md) for setup and build instructions.

## Submitting a pull request

- Keep PRs focused on one change — easier to review, easier to revert if something's wrong.
- Match the existing code style in the file you're editing.
- Describe *what* changed and *why* in the PR description.
- For anything non-trivial, consider opening an issue first to discuss the approach before investing time in the implementation.

## Code of Conduct

This project follows a [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you're expected to uphold it.
